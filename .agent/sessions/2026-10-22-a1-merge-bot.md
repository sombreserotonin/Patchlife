# 2026-10-22 A1: merge bot, licence check and renewals (MIGRATION Stage 1)

- `scripts/merge-bot.mjs` merges only PRs the App opened from `claude/reverify-*` or `claude/measures-*` in this repository, with no `needs-human` or `needs-human-merge` label, `test`, `data-gate` and `build` passed on the head SHA, and files that fit the type (MIGRATION decision 2). It squash-merges at that SHA, then deletes the branch.
- Beyond the brief, each in the direction of refusing:
  - only GitHub Actions' check runs on the head SHA count, read with `filter=all`;
  - a PR with 3000 or more files is refused, since the files API lists at most 3000;
  - the CLI refuses unknown flags (a mistyped `--dry-run` would otherwise merge), a `BOT_LOGIN` without `[bot]` and a malformed `GITHUB_REPOSITORY`;
  - branch names are escaped in the delete path (`%2e%2e` would otherwise name another ref), and control characters are escaped in what the CLI prints (a file name could otherwise start a workflow command).
- Auto-delete of head branches is on (G1), so GitHub can delete a merged branch before the bot does: a 422 "Reference does not exist" counts as deleted, and any other delete error fails the run after the merge is reported.
- `scripts/check-licences.mjs` (D9, D30): all 116 lockfile entries carry `license`, so there is no `node_modules` fallback (MIGRATION A1 suggested one); a missing licence fails instead.
- `ops/renewals.yml`, and `loadRenewals` in `scripts/renewals.mjs` for the watchdog.
