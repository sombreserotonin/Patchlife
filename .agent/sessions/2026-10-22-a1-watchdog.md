# 2026-10-22 Watchdog (MIGRATION Stage 1, A1)

- `scripts/watchdog.mjs`: the nightly alarm once no AI runs Patchlife. `gatherState` reads (GitHub REST, the site, git, the records, the renewals list), `checkState` judges, `issueBody` and `summaryText` are the fixed public templates, and `publish` dispatches Pages and keeps one `watchdog` issue. Not yet in CLAUDE.md or any workflow: both are protected, so P2 adds them.
- P2 needs: `fetch-depth: 0` (stale ages come from `git log`; a shallow clone reports every stale record as undated), `GH_TOKEN` and `GITHUB_REPOSITORY`, and a token that can read Actions, checks, contents and PRs and write issues and Actions (the Pages dispatch). reverify.yml must keep the step name "Push verification changes" and the annotation title "Records not checked".
- `scripts/renewals.mjs` (`loadRenewals`) and `ops/renewals.yml` come from another A1 lane. The CLI imports it dynamically, so until it lands every run reports "Could not read ops/renewals.yml".
- Choices beyond the plan: a deleted workflow is not an alert; a branch counts as closed unmerged when it has PRs and none is open or merged; stale records are grouped by the day they went stale; a failed read is a problem under its check and leaves that check's data unset; a renewal date that isn't a real YYYY-MM-DD is a problem; the `watchdog` label is created if missing, since GitHub's docs don't say whether a new issue's unknown label is created or dropped.
- Verified: 32 watchdog tests (boundaries at exactly 48 and 36 hours, 14 and 7 days, 2%, renewals at 61, 60, 14, 0 and -1 days; the CLI against a local fake API); 67 of 67 mutants killed; a read-only run against the repository (GETs through `gh api`) parsed every response; `npm test` 227 of 227; `npm run validate` 695 records, 0 errors.
