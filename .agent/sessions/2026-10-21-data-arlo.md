# 2026-10-21 Arlo camera and doorbell records (Crawl)

Goal: add Arlo `camera` and `doorbell` records toward M1. Result: no records added, because no Arlo source can be fetched politely by the verifier.

## What was checked
- `https://kb.arlo.com/robots.txt` (HTTP 200) ends with `User-agent: *` / `Disallow: /`. Only named search engines are allowed. `scripts/polite-fetch.mjs` correctly refuses `https://kb.arlo.com/000063018/Arlo-Legacy-Cameras-End-of-Life` with "robots.txt disallows". The end-of-life page was not read, so the "one year after the end-of-life date" wording is unconfirmed.
- `https://www.arlo.com/robots.txt` returns HTTP 403 with a Cloudflare managed challenge ("Just a moment..."). DATA-POLICY rules out CAPTCHAs, so www.arlo.com is unusable for scripts too.
- A web search (leads only) found `https://downloads.arlo.com/images/PDFs/EOL_Policy/Arlo_End-of-Life-Policy-2022.pdf`. `downloads.arlo.com` is not on the Crawl allowlist (proxy `connect_rejected`), and the verifier cannot read PDFs yet.
- No Arlo UK PSTI or Australian statement of compliance surfaced in two searches.

## Not done, on purpose
- No fetch through Claude Code's fetch tool or Firecrawl: that would sidestep robots.txt and the Cloudflare challenge, and the records still could not reach `verified`.
- No unverified records written.

## Open questions for the owner
1. Can a record cite a page whose robots.txt disallows our bot, if it is read once by hand and never re-verified by script? If yes, how does it meet the 90-day re-verification rule?
2. Add `downloads.arlo.com` to the Crawl allowlist? Useful only after PDF extraction lands.
3. Contact Arlo to allow `PatchlifeBot` in robots.txt (human gate: contacting people)?

## Inefficiency
Checking robots.txt for every new brand host before planning the records would have caught this in one request. Suggest the parent adds a robots.txt check to the brand triage step.
