# 2026-10-27: B4, the Ring, Google, GL.iNet, Kyocera and ASUS parsers, changed-row proposals and the refresh report (MIGRATION Stage 1)

Branch `claude/b4-parsers` from `claude/b3-parsers` (B3, #142, on B2, #135). Built alone; the coordinator reviews and merges.

## What changed
- `scripts/parsers/ring.mjs`: reads the GB, AU and US pages (`pages(profile)` gives the regions_by_url keys) and merges a model's rows into one candidate, regions and evidence in page order, with the row and the profile's at-least sentence from each page. The model is the name without "Ring ", or the model the profile's renames table maps the name to on that page, with the name kept as an alias; several rows of one page mapped to one model with one date are quoted together, as the records are. Different dates on different pages are a D33 split: flagged with the model, both rows skipped, nothing recorded. The 538eg name-change rows the renames table cites are quoted too, as the 14 renamed records do.
- `scripts/parsers/google.mjs`: the Nest table's release date, end date and Yes/No cell are read from the row; `addYears` is only the cross-check the validator also makes, so a row that fails it is skipped and flagged. The UK statement's "Name (CODE)" entries and each Australian statement (the profile's product-documentation URLs) link to a table model through the renames table; regions, items and the combined notes sentence follow. The dated Yes/No note follows the cell, with today's date, a No or a Yes whose minimum has passed. The regulatory page is read for Australian statements the profile does not list yet (four today). The id drops a leading "Google ".
- `scripts/parsers/gl-inet.mjs`: the PSTI minimums (id and alias from the code in brackets) and the firmware table's Maintenance rows (Supported Until, notes from the template with the dates as written); a code on both pages is a D39 case, flagged and skipped.
- `scripts/parsers/kyocera.mjs`: the page is not a table; each bold paragraph and list is a block, dates carry ordinals and the markup holds no-break spaces and a styled `<b>`.
- `scripts/parsers/asus.mjs`: the markup lists one model per `<p>` (one `<br>`), so group rows split without guessing; the quote runs from the model to the date and models whose quote would pass 300 characters are skipped, as the records were written. `table-rows.mjs` cells now carry their raw `html` for it.
- `scripts/candidates.mjs`: a brand's candidates may cite several pages; records are matched once per brand by the items only one candidate holds and counted on every parsed page they cite. Without `--check`, a record whose row changed is rewritten from the parser's row (regions, support, evidence retrieved today without archive links, notes; verification unverified; id, brand, model, aliases and category kept), exceptions are reported instead, changed rows on any brand come first and new rows follow one brand at a time within `--limit` (decision 5). `--report <file>` writes the JSON the P3 workflow builds its PR body from: today, the pages' counts, the records written (before and after for changed ones) and the flags. A parser's conflict carries its model, so one that exception records already settle (the D33 and D39 splits) is not flagged. `common.mjs` gains `monthDate`.
- `data/sources/seed.yaml` (proposals, data the owner approves): Ring's renames table gains the 27 names the ri2p1 pages write for recorded models; `ring-video-doorbell-3` ("Seed record.") joins Ring's parser_exceptions; Google gains a renames table for the 8 statement names and `min_rows` 9 for the regulatory page (its rows are its Australian statement links, 10 today).
- Synthetic fixtures (made-up models in the real markup) for the 14 new pages, fixture records parsed from them, `tests/fixtures/parsers/profiles.mjs` (the fixture profiles and page map), 6 parser tests and 15 candidates tests; README rows.

## What was inefficient
- Twenty-four Ring records (two of them the D33 exceptions) merge rows whose names differ between pages in ways no table gave (a generation spelt out, a colour list, a former name in brackets, three or four variant rows), so the renames table grew by 27 hand-kept rows rather than the parser guessing.
- The Google Yes-note depends on today against the end date, so when a Yes model's minimum passes (first: Chromecast with Google TV (HD), 22 September 2027) the gate reports a notes difference until the record or profile is updated.
- Kyocera's first block regex swallowed the page's introduction; restricting the bold text to no tags fixed it. The Google id rule (drop "Google ") and the UK statement's non-Nest groups (phones, watches) each cost a run.
