# 2026-10-27: B3, table rows, the TP-Link AU and EZVIZ parsers and candidates.mjs (MIGRATION Stage 1)

Branch `claude/b3-parsers` from `claude/b2-profiles-rules` (B2, #135). Built alone; the coordinator reviews and merges.

## What changed
- `scripts/table-rows.mjs`: the cell-based reader of MIGRATION decision 4. Splits `<tr>` and `<td>`/`<th>` on the raw HTML, runs the verifier's `htmlToText` on each cell, keeps `<sup>` content as markers beside the cell (so "Tapo C200<sup>1</sup>" gives text "Tapo C200" and marker "1"), joins the cell texts with single spaces for the row's quote, and `rowQuoteProblems` names the rows whose quote the verifier would not find in the page text.
- `scripts/parsers/common.mjs`, `tp-link-au.mjs`, `ezviz-eol.mjs`: thin parsers. The id rule, found by testing every record on the branch: `brand_slug` plus the model lowercased with each run of other characters as one hyphen (0 mismatches over 533 records). TP-Link's model is the cell's name and version as "Name (V5)", the alias is the cell as written, and the version keeps the row's casing ("v1" on two rows).
- `scripts/candidates.mjs [--check] [--limit n] [brand ...]`: fetches each parser's page with the polite fetcher, matches candidates to records by normalised quote, applies the `min_rows` gate and the parser gate, and writes new rows as unverified records. Identical duplicate rows (TP-Link lists 81 models twice) collapse into one; two different rows for one id are ambiguous and never written.
- Synthetic fixtures in `tests/fixtures/parsers/` (made-up models in the real markup) and fixture records parsed from them; `tests/table-rows.test.mjs`, `tests/parsers.test.mjs`, `tests/candidates.test.mjs`.
- README rows for the two scripts.

## How verified
- `npm test`: 333 of 333. `npm run validate`: 790 records, 16 sources, 0 errors.
- Live: `node --use-env-proxy scripts/candidates.mjs --check tp-link ezviz` reproduced 220 of 220 non-exception TP-Link records (2 exceptions with their quote on the page) and 300 of 300 EZVIZ records (11 exceptions), 0 mismatches. TP-Link: 905 rows, 36 new rows in mapped product lines, 566 skipped (539 unmapped product lines, 27 with no hardware version, including "31/6/2029" dates that are not calendar dates). EZVIZ: 311 rows, 0 new, 0 skipped.
- Write mode tried on a scratch copy of `data/devices` with `--limit 5`: five valid records, `npm run validate` clean on the copy.

## What was inefficient
- The real profiles' `min_rows` (199, 279) stop a run on the small fixtures, so the candidates tests derive profiles with `min_rows` 5 from the real registry; one test keeps the real values to show the gate.
- Early drafts counted parser-exception candidates as changed rows and ambiguous rows as gate failures; both are report-only now.
